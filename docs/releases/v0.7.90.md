# Discordmaxxer v0.7.90

This patch release hardens cross-account widget skins and profile flair
delivery when Discord or the shared metadata endpoint is temporarily late or
unavailable.

## What's changed

- A missing, malformed, or unreadable owner widget-style marker is treated as
  an availability error. The viewed profile temporarily borrows the viewer's
  selected skin while the owner marker is retried; a confirmed owner marker
  takes over when it becomes readable.
- Application-name hints are retained during marker recovery, so a profile
  card can still be matched when Discord omits its DOM application-id
  attribute.
- `showOthersBanner` remains enabled by default while settings hydrate, and
  only an explicit off value disables other users' custom banners. A deliberate
  opt-out is preserved.
- The existing profile-surface retry and animated-media handling remain in
  place, so delayed remote profile data does not permanently leave a repaired
  surface in the stock state.

Widget skins remain Discordmaxxer-rendered enhancements and do not make these
visual effects appear in vanilla Discord.
