# Discordmaxxer v0.7.116

## Highlights

- Restored the complete development build merge that was missing from the
  previous public release, including the newer DMEmoji, display-name,
  profile-cosmetics, profile-flair, widget-skin, theme, Tournament Mode, and
  performance work.
- DMEmoji now provides Unicode and server-emoji search, an iEmoji keyboard
  link, saved local media, saved-media actions, native reactions when a real
  Discord custom emoji is available, and a mouse-click Send button beside the
  composer.
- Profile presentation keeps the full animated widget/profile experience in
  normal mode while Tournament Mode pauses optional cosmetic animation and
  paint work without disabling voice, media, capture, or screenshare paths.
- Shared profile and widget rendering now uses the same owned skin/preset
  contract across the live profile, popout, activity cards, and cosmetics
  showroom instead of allowing one surface to borrow another surface's local
  selection.

## Fixed

- Hardened image and message context-menu handling so malformed props,
  non-image media, invalid child arrays, unsupported emoji references, and
  menu-construction failures fail closed instead of taking down the renderer.
  This specifically addresses the reported Discord crash after right-clicking
  a received image.
- Preserved animated banners, avatars, profile flair, and widget skins across
  refreshes and cross-client loading, with explicit reduced-motion handling in
  Tournament Mode.
- Reduced needless offscreen display-name scanning and animation retention.
- Kept profile cosmetics controls, theme visibility, readable status toasts,
  voice safeguards, and screenshare paths wired through the shared runtime
  performance bridge.

## Release boundary

The source, strict Vencord overlay, lint/type checks, plugin registry, build,
artifact integrity, and Windows x64/ARM64 packaging passed before publication.
The image-menu fix is defensive hardening and still needs a real client test
with a normal image, GIF, and image link. Voice quality, screenshare quality,
cross-PC profile rendering, and comparative stock-Discord benchmarks remain
runtime/user acceptance checks rather than claims made by this release.
