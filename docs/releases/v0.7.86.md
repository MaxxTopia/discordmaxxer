# Discordmaxxer v0.7.86

**Attempt #8 at fixing skin application to an already-published profile widget.**
This release also attempts to restore profile-flair banners when Discord recycles
profile elements.

## What's changed

- Applying a skin now waits for any stale widget-profile read, fetches the
  attached widgets again, and styles only widgets confirmed as belonging to the
  signed-in account.
- Discordmaxxer verifies the exact visible Board card and selected skin before
  reporting that an existing widget was updated. Incomplete or unknown Discord
  responses preserve the last-confirmed widget mapping instead of treating it
  as an empty Board.
- Skin selection remains local to Discordmaxxer: it does not republish or
  change the native Discord widget card. The Discordmaxxer Playing card follows
  the widget's selected style when its matching card is visible.
- Profile flair keeps static avatar/banner media visible in Tournament Mode,
  recognizes animated Discord avatar hashes served as WebP, and retries banner
  rendering with bounded backoff when Discord recycles the profile element.

Widget skins and profile flair are Discordmaxxer-rendered enhancements; this
does not make those visual effects appear in vanilla Discord. Account-specific
rendering still needs confirmation in the affected signed-in client after
updating.
