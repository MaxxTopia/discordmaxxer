# Discordmaxxer v0.7.146

## Highlights

- **Fix DMWidget Crash Caused by Discord Nuking `localStorage`**:
  - **Root Cause**: Modern Discord builds execute `delete window.localStorage` to prevent token theft from injected scripts. Evaluating bare `localStorage` (such as `localStorage.getItem(...)` or `localStorage.setItem(...)`) in strict/renderer contexts throws `ReferenceError: localStorage is not defined`.
  - When opening the DMWidget settings modal, both `WidgetStylePicker` (rendered via `settingsAboutComponent`) and `WidgetEditor` (rendered via setting `editor`) invoked `getEffectiveRiotId()` and `getEffectiveFnIgn()`, which accessed bare `localStorage`. This caused Vencord's ErrorBoundary to catch the unhandled `ReferenceError` and replace both components with the red error box:
    - `"Oh no! An error occurred while rendering this plugin's custom Info Component. ReferenceError: localStorage is not defined"`
    - `"Oh no! An error occurred while rendering setting "editor". ReferenceError: localStorage is not defined"`
  - **Resolution**:
    - Replaced all bare `localStorage` reads/writes in `plugins/DMWidget/index.tsx` with a dual-tier `safeGetItem()` and `safeSetItem()` storage engine:
      - Memory-backed `Map<string, string>` for instant synchronous reads during component render.
      - Optional chaining on `(globalThis as any).localStorage?.getItem?.(...)` and `.setItem?.(...)`, preventing `ReferenceError` throws even when `window.localStorage` is deleted.
      - Asynchronous mirroring and hydration via Vencord's IndexedDB `DataStore`.
    - Eliminated bare `localStorage` in `plugins/DMVoiceKeybinds/index.ts` in favor of guarded `(globalThis as any).localStorage`.
    - Restored the DMWidget visual showroom (`WidgetStylePicker`), skin preset cards, live preview, action buttons, and full widget editor.
