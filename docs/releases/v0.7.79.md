# Discordmaxxer v0.7.79

This patch reduces shared-roster refresh pressure without changing roster
authority or the existing last-known-good behavior.

## What's changed

- Shared roster requests now use a normal cacheable GET instead of a unique
  cache-busting URL and custom no-cache headers.
- The Worker serves the shared roster from a fixed 30-second edge-cache key
  before reading KV, including for older clients that still send the old
  `dmx_refresh` query parameter.
- The existing 30-second client freshness window, retry/backoff behavior,
  sanitization, payload shape, and optimistic profile behavior are unchanged.

## Visibility boundary

The roster remains authoritative for Discordmaxxer-rendered profile features;
this change does not make those features native Discord fields. The Worker
must be deployed before publishing this client patch.
