# Discordmaxxer v0.7.96

This release improves cross-PC profile media rendering and makes Playlistmaxxing
presence recover reliably when the client starts after a track is already
playing.

## Highlights

- Fixed cross-PC profile banners being attached to the wrong recycled Discord
  profile view or appearing as a plain native background.
- Extensionless Worker-hosted animated banners are now rendered as real image
  media, with ownership guards so a late load cannot paint another user's
  profile.
- Animated profile media resumes when it becomes visible again or the client
  returns from the background. Tournament Mode's intentional pause remains
  unchanged.
- Playlistmaxxing Presence now catches up to the current track at startup and
  during reconnects, keeps live tracks visible regardless of the idle-fallback
  setting, and uses the track's public artwork when available.

## Setup and limits

- Both Discordmaxxer clients must be updated before judging the cross-PC banner
  fix. The recipient test is still a real signed-in DiggyT-to-DiggyAI check.
- Playlistmaxxing Presence requires Streammaxxing to be running and the
  Playlistmaxxing Broadcast control enabled on the same PC. Pressing play on
  the website alone does not send the cross-app bridge event.
- Vanilla Discord still cannot render Discordmaxxer-only profile media or
  widgets.
