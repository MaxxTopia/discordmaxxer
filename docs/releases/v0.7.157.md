# Discordmaxxer v0.7.157

## Highlights

This maintenance release hardens image and video attachments in DM composers.

It also shortens the startup failure window and begins readiness checks at
navigation commit, so a usable Discord surface is not held behind a slow page
resource or left on the remote "Opening Discord App" shell.

## Fixed

- Keep a pending image or video preview visible while Discord replaces the
  upload store or composer form during an upload.
- Show a named, actionable fallback when media preview decoding or object-URL
  creation fails instead of leaving a blank attachment surface.
- Restore view/lightbox and remove actions for pending attachments, with remove
  updating the visible card immediately after Discord accepts it.
- Support current and legacy Discord upload-store return shapes.
- Start the renderer readiness probe at navigation commit and require a visible
  Discord surface before stopping the startup watchdog.
- Reduce the bounded startup recovery timeout from 25 seconds to 18 seconds.

## Verification

The candidate passed the project test suite, strict Vencord overlay build,
artifact-integrity verification, and Windows packaging checks. A signed-in
image/video DM send, view, and remove test remains a user acceptance check
after installation.
