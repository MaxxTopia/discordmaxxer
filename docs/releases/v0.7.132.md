# Discordmaxxer v0.7.132

## Highlights

- Adds an opt-in outgoing microphone boost in DMMicMonitor. The processed microphone track is the one Discord sends to voice-call recipients; the local sidetone and level meter remain separate controls.
- Adds a guarded Web Audio fallback: if the runtime refuses the processing graph, Discord keeps the original microphone stream instead of going silent.
- Keeps screen-share video and audio outside the microphone boost path. The Linux compatibility path also marks screen-share capture so microphone-only processing cannot intercept it.
- Keeps the existing single-key voice-keybind support and the v0.7.131 startup, composer, image-menu, folder, widget, Spotify, and DMTrim fixes in the release line.

## Verification

- application build and Windows packaging

## Runtime boundary

The outgoing gain remains off by default. Enable it from DMHub -> Voice & input -> Mic boost, sidetone & level monitor, use headphones for local monitoring, then reconnect voice if already in a call. A real recipient test is still required to confirm perceived loudness and clarity on the user's hardware; automated build checks cannot prove that.
