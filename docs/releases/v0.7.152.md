# Discordmaxxer v0.7.152

## Highlights

- **Keep the account bar intact in Streamer Mode:** narrowed the Quest-ad cleanup selectors so they cannot collide with Discord's account panel, and constrained the DMHub quick-toggle slot to its intended 32px surface.
- **Make widget refresh honest and safer:** live stats use the owner-controlled stats service when available, personal provider keys remain an explicit fallback, and Update/Deploy reports whether Discord actually refreshed the current profile or tells the user exactly when to reopen it or press `Ctrl+R`.
- **Harden renderer recovery:** a renderer that dies after startup now gets bounded reload attempts before Discordmaxxer opens its existing recovery screen instead of leaving a Chromium crash page visible.
- **Respect video-only screen shares:** application audio is not injected when the actual capture request explicitly asks for video only.
- **Hide the arRPC scan console:** the Windows process probe no longer flashes a console window during Rich Presence discovery.

## Verification

- Lint and TypeScript checks passed with `pnpm test`.
- Plugin registry, strict pinned-Vencord overlay, build-integrity checks, Windows audio tests, and packaged-directory verification passed locally.
- The packaged candidate was launched with the imported signed-in profile. The full account bar, username, Spotify slot, DMHub quick-toggle, mute/deafen, input/output options, and user-settings control were present in the accessibility tree.
- Streamer Mode on/off runtime checks confirmed that the account panel remains visible and usable; the package contains the narrowed Quest selectors and no longer contains the broad selectors that caused the collision.
- A matched guarded idle benchmark was recorded for Discordmaxxer and stock Discord. It is process CPU/RAM evidence only, not a gameplay, voice, screenshare-recipient, or visual-quality claim.
