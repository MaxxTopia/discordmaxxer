# Discordmaxxer v0.7.100

## Highlights

This release hardens cross-account profile rendering so Discordmaxxer users
see the owner's saved presentation instead of a temporary native card or the
viewer's local styling.

## Fixed

- Fixed widget-skin ownership hydration so Valorant, Fortnite, and other
  supported widget cards resolve from the profile owner, not the person
  viewing the profile.
- Preserved the last confirmed widget skin while Discord profile data is still
  loading, preventing a brief skinless/default flash during profile opens,
  account switches, and refreshes.
- Added a bounded migration for older locally-selected widget skins so the
  owner's saved style can be shared with other Discordmaxxer installs without
  rewriting widget content or repeatedly spending API requests.
- Kept stale or incomplete roster responses from clearing the last-known-good
  banner, avatar, profile-color, and widget presentation state. Retries use
  backoff instead of hammering the Worker or Discord endpoints.
- Improved display-name style discovery in profile popouts and other profile
  surfaces after Discord mounts its visual markers, while keeping message,
  member-list, and profile controls independently configurable.

## Notes

- Discordmaxxer-only banners, widgets, flair, and profile colors still require
  Discordmaxxer on the viewing device. Vanilla Discord cannot render these
  client-side enhancements.
- This release does not change native Discord content, widget statistics, or
  the user's selected media; it only makes the owner-scoped renderer and its
  recovery behavior more reliable.
