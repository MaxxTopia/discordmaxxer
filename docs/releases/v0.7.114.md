# Discordmaxxer v0.7.114

## Highlights

This release delivers critical voice audio safeguards and priority shielding. Discord's WebRTC audio engine, Opus decoder, and NetEq jitter buffers are now permanently shielded at full normal priority class, preventing audio buffer underruns, static, and crackling while gaming in Tournament Mode. In addition, universal voice connection detection now covers all 1-on-1 DM calls, Group DM calls, and server voice channels with zero background audio throttling.

## Voice Audio & Stability Safeguards

- **Shielded WebRTC & Media Process Priorities:**
  - Guaranteed that the Renderer process (where WebRTC Opus encode/decode and NetEq jitter buffer run) and audio utility processes are never dropped below `PRIORITY_NORMAL`.
  - Windows scheduler can no longer starve Discord's audio decoding threads when a game spikes CPU usage, eliminating audio buffer underruns, clicks, pops, and static.
- **Universal Voice Connection Detection:**
  - Expanded voice state tracking across `SelectedChannelStore`, `RTCConnectionStore`, `ChannelRTCStore`, and native `RTCPeerConnection` listeners.
  - Active 1-on-1 direct message calls and Group DM calls are now immediately recognized by the system performance bridge alongside server voice channels.
- **Background Audio Clock Protection:**
  - Maintained `--disable-background-timer-throttling` on Chromium command line so 20ms WebRTC audio packet intervals are never bunched or delayed into 1000ms bursts when Discord is unfocused or on a second monitor.
  - Guarded window minimize handlers to strictly never apply timer throttling to active audio contexts.
