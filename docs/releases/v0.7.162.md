# Discordmaxxer v0.7.162

## Highlights

This maintenance release carries the upstream-compatibility repair and makes
the automated dependency watchers safer and quieter without changing the
client's normal Discord workflow.

## Fixed

- Align the Vencord overlay with the pinned upstream 1.15.19 module shapes,
  including the compatibility boundaries needed by the renderer and custom
  plugins.
- Keep the release workflow and overlay metadata on the same Vencord commit,
  use the required Node/Corepack toolchain, and fail closed on overlay or
  artifact-integrity warnings before publication.
- Deduplicate unchanged upstream-drift issues and Maxx-bot notifications so
  scheduled and manual watcher runs do not create repeated alerts.
- Preserve the existing startup, DM, widget, skin, cursor, voice-safeguard,
  and Tournament Mode behavior covered by the candidate verification.

## Verification

The candidate passed the documented TypeScript/ESLint checks, strict Vencord
overlay, plugin and artifact verification, and production build. The local
Windows host ran out of practical packaging space while assembling the
Electron directory, so the clean release workflow remains the authoritative
directory/installer/ZIP packaging gate for this tag. The default-device audio
probe received no capture chunks in two seconds; no native audio source
changed, and this host limitation is not presented as a clean audio pass.

An earlier packaged candidate was manually smoke-tested signed in for normal
Discord navigation and interaction after disabling the optional Discordmaxxer
theme palette. Live voice/screenshare recipient behavior remains an optional
device-side check and is not claimed by this release note.
