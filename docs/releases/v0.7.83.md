# Discordmaxxer v0.7.83

This release reduces background license-roster traffic so the shared VIP data
service is less likely to exhaust its account-wide daily KV read allowance.

## What's changed

- Normal roster refreshes now use a five-minute local freshness window while
  keeping the existing last-known-good snapshot, retry behavior, claims, and
  profile flair rendering.
- The Worker serves the shared roster from a two-minute fixed-key edge cache,
  so normal refreshes do not repeat the claim/profile KV reads at every client.
- Authenticated admin list and offer display responses use a short edge cache;
  admin mutations clear the display cache before changing data. Validation,
  claims, profile writes, and authentication remain authoritative and uncached.

This is a read-efficiency and resilience change. It does not change tier
entitlements, claim ownership, profile-flair fields, or vanilla Discord
rendering.
