# Discordmaxxer v0.7.99

## Highlights

This release finishes the cross-account profile presentation pass and restores
the display-name styling surface that was missing from the previous public
build. It also makes the first-run DM Hub easier to understand without changing
the free profile customization or the media playback safeguards.

## Fixed

- Fixed display-name styles so the selected style can apply to visible message
  author labels, profile popouts, member rows, and DM headers. Each surface has
  its own setting, so messages can be disabled without removing profile or
  member styling.
- Fixed cross-account widget-skin isolation. A profile card no longer borrows
  the viewer's local widget skin while the owner's published marker is being
  read. Unknown owner state stays native until the exact owner skin is ready,
  preventing another account's skin from appearing on the profile.
- Kept the last known good profile roster/media state during refresh, and kept
  in-view banner/avatar playback tied to visibility so profiles do not flash to
  native defaults or stop animating merely because a refresh is in progress.
- Added a small DM Hub scroll cue after the identity controls so the profile
  gradient, profile-media controls, plugin health, and featured-plugin sections
  are discoverable without removing the existing gradient choices.
- Kept the real Discordmaxxer badge artwork in the DM Hub welcome card instead
  of an empty placeholder preview.

## Included from the preceding profile-media work

- Free users retain the full-quality animated profile banner, animated avatar,
  and profile colors. Paid tiers add presentation controls and capacity; they
  do not reduce the free media quality.
- Profile-owned widget styles, cross-PC profile media, the R2-backed roster
  snapshot, Playlistmaxxing live presence polling, direct track artwork, and
  the readable release-alert guard remain included from v0.7.96-v0.7.98.

Discordmaxxer-only banners, widgets, flair, and profile colors still require
the Discordmaxxer client on the viewing device; vanilla Discord cannot render
these client-side enhancements.
