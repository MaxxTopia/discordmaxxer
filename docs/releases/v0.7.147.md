# Discordmaxxer v0.7.147

## Highlights

- **Fix DMWidget Hero Image Layout Banner (Unboxed Hero) vs Boxed Display**:
  - **Root Cause**:
    - When selecting skin presets that default to `topLayout: "contained"` (such as "Mothlight Reliquary" / `emberProtocol`), `choose(preset)` previously assigned `slot.topLayout = "contained"`.
    - When switching the "Top Layout" dropdown in settings to "Banner" (`hero`), `definePluginSettings.topLayout` lacked an `onChange` callback, so only `settings.store.topLayout` changed while `slot.topLayout` remained `"contained"`.
    - In `buildSurfaces`, `savedSlot.topLayout ?? s.topLayout` favored `savedSlot.topLayout`, keeping `selectedTopLayout` as `"contained"` and constructing `layout: "widget_top_contained"` for Discord's API.
    - When clicking "Apply skin to existing widget", `republishSelectedWidgetStyleUnsafe` hydrated remote published content from Discord (which was still `widget_top_contained`) and overwrote `latest.topLayout` back to `"contained"`.
    - In Discordmaxxer's client CSS, `.containedImage` and `.imageContainer` lacked rules to strip Discord's grey rounded-rectangle background and border when `data-dm-widget-top-layout="hero"`.
  - **Resolution**:
    - **Interactive Image Layout Toggle in Showroom**: Added a dedicated segmented button row (`[Banner (Unboxed hero)]` / `[Boxed]`) right above the live preview in `WidgetStylePicker`. Clicking "Banner (Unboxed hero)" immediately sets `slot.topLayout = "hero"`, updates `settings.store.topLayout = "hero"`, syncs attached widget styles, triggers an immediate DOM scan, updates the preview, and publishes `widget_top_hero` to Discord's Social SDK API.
    - **Preserve User Choice on Preset Switch**: In both `choose(preset)` and the lower preset gallery, user explicit layout choice (`"hero"` or `"contained"`) takes precedence over preset defaults, preventing "Mothlight Reliquary" from clobbering "Banner".
    - **Two-Way Sync on Apply Skin and Update Content**:
      - In `republishSelectedWidgetStyleUnsafe`, user choice takes precedence over Discord's remote published snapshot; if the published layout on Discord differs from the local layout, it automatically republishes the config so Discord updates to `widget_top_hero`.
      - In `deployWidget` and `buildSurfaces`, explicit "hero" choice takes precedence so `layout: "widget_top_hero"` with `hero_image` is published to Discord.
    - **Setting `onChange` Callback**: Added `onChange(v)` to `definePluginSettings.topLayout` so selecting "Banner" in settings updates the slot, syncs attached widget styles, triggers an immediate DOM scan, and republishes to Discord.
    - **Client CSS Unboxed Hero Presentation**: Added scoped CSS targeting `[data-dm-widget-card-root="true"][data-dm-widget-top-layout="hero"]` to strip background color, borders, and box shadows on contained image containers and apply a glowing neon drop-shadow to the hero image cutout, ensuring the hero stands unboxed directly over the card background.
