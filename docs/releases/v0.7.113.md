# Discordmaxxer v0.7.113

## Highlights

This release delivers major resource-efficiency and background performance upgrades across Discordmaxxer. Custom anime cursors and profile widgets are now hardware-accelerated directly on the GPU compositor, background animations freeze to 0% CPU when unfocused or stationary, and voice-aware background throttling drops idle resource usage to match or beat stock Discord without compromising voice calls or gaming streams.

## Performance & Optimization

- **Pure GPU Compositor Keyframes for DMCursor:**
  - Replaced CPU-heavy SMIL `<animateTransform>` tags in Sharingan, Rinnegan, and Rasengan SVG skins with hardware-accelerated CSS compositor `@keyframes`.
  - SVG layout tree geometry is no longer recalculated synchronously on the V8 main thread on every frame, eliminating CPU spikes and software rasterization stalls.
- **Smart Pointer Idle & Focus Freeze:**
  - Cursor animations automatically sleep when the pointer is stationary for more than 2.5 seconds, instantly re-engaging the moment the mouse moves.
  - Animations immediately freeze when Discord is blurred or the cursor leaves the window, guaranteeing 0% cursor CPU while reading chat, typing, or playing a game on another monitor.
- **DMWidget GPU Compositor Layer Promotion:**
  - Promoted `[data-dm-widget-skin]::before` and `::after` layers to dedicated GPU surfaces with `will-change: transform, opacity; transform: translateZ(0);`.
  - Added `:root:not(:focus-within)` rules so widget skin glow and motion loops immediately pause when Discord is unfocused.
- **TournamentMode Full Animation Freeze:**
  - Integrated DMWidget skin cards and surface backgrounds into TournamentMode's `PERF_CSS`, immediately halting all cosmetic animation loops during competitive gaming sessions.
- **Voice-Aware Background Throttling & RAM Trim:**
  - Discordmaxxer dynamically throttles background JS timers and clears in-memory V8 code caches when minimized or hidden outside of voice calls.
  - When in a voice call or screenshare, background throttling is strictly disengaged to preserve WebRTC Opus encoding and audio stream fidelity.
